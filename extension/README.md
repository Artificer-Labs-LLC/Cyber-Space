# Cyberspace Resolver — browser extension

Resolves `.cyberspace` names. Type `genesis.cyberspace` in the address bar and it just works.

## How it works

- The service worker (`background.js`) listens for top-frame navigations to `*.cyberspace` and resolves the name through the genesis DoH bridge (`http://185.143.228.228/dns-query`) before the page loads, redirecting the tab to the claimed node's IP.
- The shared DoH client lives in `resolver.js` (loaded by the background via `importScripts`, by the popup via `<script>`).
- Unclaimed or unreachable names land on an inline error page naming the failed name and reason — never a dead address.
- The popup (`popup.html`/`popup.js`) health-checks the bridge on open (result cached 60s in `chrome.storage.local`), shows `resolving <name> …` while a resolve is in flight (Go disables to prevent double-submits), and confirms `opened <name> → <ip>` on success.
- The popup remembers your last five successfully visited places as clickable chips (dedupe, newest first) — a click revisits through the same single-flight resolve path, and a goFlight guard at the top of resolveAndOpen covers all Go-path entry points (Go button, Enter, chips) so a rapid double click anywhere opens exactly one tab; the button's `disabled` is now purely visual feedback.
- Open the popup any time with **Alt+Shift+C** (`commands._execute_action`).

## Install (Chrome / Edge / Chromium)

1. Go to `chrome://extensions`, enable **Developer mode**.
2. **Load unpacked** → select this `extension/` folder.
3. Click the Cyberspace action icon → resolve any `*.cyberspace` name, or just type one in the address bar.

## Permissions

- `webNavigation` + `tabs` — intercept `*.cyberspace` navigation, redirect on resolve.
- `host_permissions` `http://185.143.228.228/*` (2026-10-09, minimalized) — the pinned genesis bridge origin only; install-time footprint is one IP. `optional_host_permissions` `*://*/*` — custom bridges (options page + popup quick-change) cannot be pinned, so each bridge-save requests **just its own origin** (`origin + "/*"`, shared `saveBridgeSetting`/`ensureBridgeHostPermission` in resolver.js) before persisting; a denied grant leaves the stored bridge untouched. An options-page on-load banner catches bridges stored before this gating pass: a stored custom bridge missing its origin grant (detected with a read-only `permissions.contains` — no prompt without a gesture) shows an amber Grant-access banner, and the grant rides the banner's own button click. Under MV3 a host missing from the granted set silently blocks the bridge fetch, which is why the grant gates the save — a bridge saved without its grant would die on every later resolve. Single-fetch invariant (audited 2026-10-08 17:00): the extension carries exactly one `fetch` call site (`fetchRound` in resolver.js), always to the scheme-validated bridge URL — no `XMLHttpRequest`, `EventSource`, `WebSocket`, or `sendBeacon` anywhere, and both address-bar/popup redirects go through `chrome.tabs.update` navigation, never fetch — so any granted origin can only ever move DNS-shaped bytes to the bridge the user chose, never page content anywhere else.
- `storage` — persists the last successfully resolved name (prefilled into the popup input on open), the 60s health-check cache, the configured DoH bridge endpoint (changeable in the popup's "Bridge endpoint" section or the options page; a custom bridge is requested at save time via optional_host_permissions (origin-scoped), so it resolves from the moment the user approves it — no manifest edit needed), and the five most recent visited places.
